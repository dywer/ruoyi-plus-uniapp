# 多智能体工作流技能 (Multi-Agent Workflow)

## 适用场景
- 复杂功能开发需要多角色协作
- 大型重构任务需要多视角分析
- 架构决策需要多专家评估
- 代码审查需要多维度检查

## 核心概念

### 什么是多智能体工作流
多智能体工作流 (Multi-Agent Workflow) 是一种将复杂任务分解为多个子任务，由不同的 AI 实例并行或串行处理的协作模式。

```
┌─────────────────────────────────────────────────────────┐
│                    主协调器 (Orchestrator)                │
└─────────────────────────────────────────────────────────┘
                            │
         ┌──────────────────┼──────────────────┐
         ▼                  ▼                  ▼
┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐
│   架构师 Agent   │ │   开发者 Agent   │ │   测试者 Agent   │
│  (Architect)    │ │   (Developer)   │ │    (Tester)     │
└─────────────────┘ └─────────────────┘ └─────────────────┘
         │                  │                  │
         └──────────────────┼──────────────────┘
                            ▼
                  ┌─────────────────┐
                  │   整合输出       │
                  │  (Consolidate)  │
                  └─────────────────┘
```

## 智能体角色定义

### 1. 架构师 (Architect)
**职责**: 系统设计、技术选型、架构模式

**触发词**: "架构设计"、"系统设计"、"技术选型"、"重构"

**专长**:
- DDD 领域驱动设计
- 微服务架构
- 六边形架构
- Clean Architecture
- 设计模式应用

**示例 prompt**:
```
作为资深架构师，请分析以下需求并设计系统架构：
- 业务目标：{target}
- 技术约束：{constraints}
- 性能要求：{requirements}

请输出：
1. 架构图
2. 技术选型理由
3. 关键设计决策
4. 风险评估
```

### 2. 开发者 (Developer)
**职责**: 代码实现、单元测试、代码优化

**触发词**: "实现功能"、"编写代码"、"优化性能"、"重构代码"

**专长**:
- Spring Boot 开发
- Vue 3 前端开发
- MyBatis-Plus ORM
- RESTful API 设计
- 代码重构

**示例 prompt**:
```
作为资深开发者，请实现以下功能：
- 功能描述：{feature}
- 输入参数：{input}
- 预期输出：{output}

请输出：
1. 完整的代码实现
2. 单元测试
3. 使用示例
```

### 3. 测试者 (Tester)
**职责**: 测试用例设计、边界条件验证、质量保障

**触发词**: "测试"、"验证"、"边界条件"、"质量检查"

**专长**:
- 单元测试 (JUnit 5, Vitest)
- 集成测试 (Testcontainers)
- E2E 测试 (Playwright)
- 边界条件分析
- 回归测试

**示例 prompt**:
```
作为测试专家，请为以下功能设计测试用例：
- 功能描述：{feature}
- 输入范围：{inputRange}

请输出：
1. 正常场景测试
2. 边界条件测试
3. 异常场景测试
4. 性能测试建议
```

### 4. 安全专家 (Security Expert)
**职责**: 安全漏洞检测、OWASP 合规、安全加固

**触发词**: "安全"、"漏洞"、"渗透测试"、"代码审计"

**专长**:
- OWASP Top 10 检测
- SQL 注入防护
- XSS 攻击防护
- CSRF 防护
- 认证授权审查

**示例 prompt**:
```
作为安全专家，请审查以下代码的安全性：
- 代码范围：{scope}
- 关注点：{concerns}

请输出：
1. 潜在安全风险
2. 漏洞等级评估
3. 修复建议
4. 安全加固方案
```

### 5. 性能专家 (Performance Expert)
**职责**: 性能分析、瓶颈识别、优化建议

**触发词**: "性能优化"、"瓶颈"、"响应时间"、"吞吐量"

**专长**:
- 性能 profiling
- 数据库优化
- 缓存策略
- 并发处理
- 资源优化

**示例 prompt**:
```
作为性能专家，请分析以下系统的性能瓶颈：
- 当前性能：{metrics}
- 目标性能：{target}

请输出：
1. 瓶颈分析
2. 优化方案
3. 预期提升
4. 验证方法
```

### 6. 代码审查者 (Code Reviewer)
**职责**: 代码质量审查、规范检查、改进建议

**触发词**: "代码审查"、"CR"、"代码质量"、"规范检查"

**专长**:
- 代码规范审查
- 可维护性评估
- 可读性检查
- 复杂度分析
- 最佳实践验证

**示例 prompt**:
```
作为代码审查专家，请审查以下代码：
- 审查范围：{scope}
- 关注点：{focus}

请输出：
1. 问题清单 (按严重程度)
2. 改进建议
3. 最佳实践建议
4. 技术债务评估
```

## 多智能体协作模式

### 模式 1: 并行评审 (Parallel Review)
```
适用场景：代码审查、架构评审、安全审计

流程:
1. 主协调器分发任务给多个专家
2. 各专家并行独立评审
3. 收集所有评审意见
4. 整合输出综合报告
```

**示例**:
```yaml
任务：新功能代码审查
参与 Agent:
  - code-reviewer: 代码规范审查
  - security-reviewer: 安全漏洞检查
  - performance-reviewer: 性能影响评估
  
输出：综合审查报告
```

### 模式 2: 接力协作 (Relay Collaboration)
```
适用场景：完整功能开发、大型重构

流程:
1. 架构师设计系统架构
2. 开发者实现代码
3. 测试者编写测试
4. 审查者最终审查
```

**示例**:
```yaml
任务：用户管理模块开发
阶段 1: 架构师设计数据模型和 API 结构
阶段 2: 开发者实现 CRUD 操作
阶段 3: 测试者编写单元和集成测试
阶段 4: 审查者进行最终代码审查
```

### 模式 3: 迭代优化 (Iterative Optimization)
```
适用场景：性能优化、复杂 bug 修复

流程:
1. 性能专家分析瓶颈
2. 开发者实施优化
3. 测试者验证效果
4. 循环迭代直到达标
```

### 模式 4: 红蓝对抗 (Red Team vs Blue Team)
```
适用场景：安全审计、系统设计验证

流程:
1. 红队 (攻击方): 寻找漏洞和问题
2. 蓝队 (防守方): 提供解决方案
3. 协调者评估双方意见
4. 输出平衡的决策建议
```

## 实际应用示例

### 示例 1: 复杂功能开发
```yaml
需求：实现多租户 SaaS 功能

Agent 分工:
  - 架构师：设计租户隔离方案和数据模型
  - 开发者：实现 TenantEntity 基类和自动填充
  - 安全专家：审查租户数据隔离安全性
  - 测试者：设计多租户场景测试用例
  - 审查者：最终代码质量审查

预期产出:
  - 架构设计文档
  - 完整代码实现
  - 安全审计报告
  - 测试用例集
  - 代码审查报告
```

### 示例 2: 系统重构
```yaml
需求：将单体应用重构为微服务

Agent 分工:
  - 架构师：设计微服务拆分方案
  - 开发者：实现服务拆分和接口改造
  - 性能专家：评估拆分后的性能影响
  - 安全专家：审查服务间通信安全
  - 测试者：设计集成测试和契约测试

预期产出:
  - 微服务架构图
  - 服务接口定义
  - 性能基准报告
  - 安全方案
  - 测试策略
```

### 示例 3: 安全审计
```yaml
需求：全面安全审计

Agent 分工:
  - 安全专家 (红队): 寻找安全漏洞
  - 安全专家 (蓝队): 提供修复方案
  - 代码审查者：检查代码规范
  - 性能专家：评估安全措施的性
