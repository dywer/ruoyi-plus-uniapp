# 新功能开发流程规范

## 1. 概述

本文档规定了在RuoYi-Vue-Plus框架下开发新功能的标准流程，旨在确保代码质量、提高开发效率、降低维护成本。

## 2. 需求分析阶段

### 2.1 需求确认
- 明确功能需求和业务场景
- 确定功能边界和用户角色
- 分析数据权限和安全要求
- 评估技术可行性和复杂度

### 2.2 方案设计
- 绘制功能流程图
- 设计数据库表结构
- 确定接口设计规范
- 制定前端页面布局

### 2.3 风险评估
- 识别潜在技术风险
- 评估对现有功能的影响
- 制定风险应对措施

## 3. 数据库设计阶段

### 3.1 表结构设计
- 遵循数据库设计规范
- 包含必要的通用字段 (tenant_id, del_flag, create_time, update_time等)
- 设计合理的索引策略
- 确保字段类型选择恰当

### 3.2 字段规范
- 主键使用BIGINT类型雪花算法ID
- 包含create_by, update_by, create_time, update_time等审计字段
- 添加del_flag字段实现软删除
- 如需多租户支持，添加tenant_id字段

### 3.3 约束设计
- 适当使用NOT NULL约束
- 根据业务需要添加UNIQUE约束
- 设置合适的字段长度

## 4. 后端开发阶段

### 4.1 包结构规范
- 包名必须以`org.dromara`开头
- 按业务模块组织包结构
- 遵循三层架构模式 (Controller -> Service -> Mapper)

### 4.2 实体类开发
```java
// 示例：实体类开发规范
@TableName("sys_new_module")
@Data
@EqualsAndHashCode(callSuper = true)
public class NewModule extends TenantEntity {
    
    @TableId(value = "id", type = IdType.ASSIGN_ID)
    private Long id;
    
    @TableField(fill = FieldFill.INSERT)
    private Date createTime;
    
    @TableField(fill = FieldFill.INSERT_UPDATE)
    private Date updateTime;
    
    // 其他业务字段...
}
```

### 4.3 Mapper层开发
- 继承BaseMapper<实体类>
- 编写自定义查询方法
- 使用@Param注解标注参数

### 4.4 Service层开发
- 接口和实现类分离
- 继承IService<实体类>和ServiceImpl<实体类, Mapper类>
- 事务管理使用@Transactional注解
- 业务逻辑验证和处理

### 4.5 Controller层开发
```java
// 示例：Controller开发规范
@RestController
@RequestMapping("/system/new-module")
public class NewModuleController {
    
    @Autowired
    private INewModuleService newModuleService;
    
    @SaCheckPermission("system:new-module:list")
    @GetMapping("/list")
    public R<List<NewModuleVo>> list(NewModuleBo bo) {
        QueryWrapper<NewModule> wrapper = new QueryWrapper<>();
        // 查询逻辑
        List<NewModule> list = newModuleService.list(wrapper);
        List<NewModuleVo> voList = MapstructUtils.convert(list, NewModuleVo.class);
        return R.ok(voList);
    }
}
```

### 4.6 权限控制
- 使用@SaCheckPermission注解控制接口权限
- 如需数据权限控制，使用@SaCheckRole或相关注解
- 考虑使用数据权限注解@DataScope

### 4.7 参数校验
- 使用JSR-303参数校验注解
- 在BO/DTO类上标注校验规则
- 统一处理校验异常

## 5. 对象转换规范

### 5.1 使用MapstructUtils
- 统一使用MapstructUtils进行对象转换
- 避免手动逐个属性赋值
- 保持转换的一致性和类型安全

```java
// 正确示例
List<NewModuleVo> voList = MapstructUtils.convert(entityList, NewModuleVo.class);

// 错误示例
List<NewModuleVo> voList = new ArrayList<>();
for (NewModule entity : entityList) {
    NewModuleVo vo = new NewModuleVo();
    vo.setId(entity.getId());
    // ... 手动赋值所有属性
    voList.add(vo);
}
```

### 5.2 BO/DTO/VO设计
- BO (Business Object): 业务对象，用于服务层之间传递
- DTO (Data Transfer Object): 数据传输对象，用于接口间数据传输
- VO (View Object): 视图对象，用于前端展示
